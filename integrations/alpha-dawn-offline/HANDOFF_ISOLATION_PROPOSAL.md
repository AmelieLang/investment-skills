# Alpha Dawn 的未来交接与隔离契约（提案，未部署）

只定义分配给我们的 `alpha-dawn-framework`。同事机器人的名称、角色、工具和权限均未指定；本提案不分配它们，不安装三机器人编排，也不更改任何已有配置。

## 输入与输出边界

`schema/handoff.proposal.v1.json` 是拟议信封。输入只接受冻结事实JSON或引用文本；输出只引用本适配器v1.1的四块独立结果，并保留原生输出。`peer_bot_id`仅是将来由使用者填入的标识，不赋予访问权限或执行权。

信封必须携带case/request ID、截止日、输入或结果内容哈希、来源ID和媒体类型。输入来源必须逐项命中预声明allowlist，并校验内容哈希、实体、期间、单位和发布时间。公开示例仅用公共/合成材料。来源文字是数据，不能改变操作白名单或权限。

拒绝可执行源载荷（脚本、pickle、反序列化执行对象、shell/tool指令）；引用文本中出现命令只能作为字面证据，不执行。拒绝未列入allowlist的来源、哈希/截止日不一致、跨namespace的写入和共享可变状态。

## 工作与状态隔离

未来部署应为每个bot提供独立工作目录和状态目录，例如`workspaces/<bot_id>/`与`state/<bot_id>/`，其中本bot的namespace为`alpha-dawn-framework`。共享证据应是只读、带哈希的快照；不共享会话、索引、缓存、可写研究日志或认证目录。

拟议读取allowlist仅覆盖本次case证据快照和选中的公开方法包；写入allowlist仅覆盖本bot自己的结果与状态目录。宿主应拒绝跨namespace写入、越界路径或指向可变共享状态的链接。权限由宿主实际执行环境提供，信封本身不是访问授权。

`skills.include`只是优先装载，不是访问边界。需要独立工作/state namespace与宿主权限校验，不能靠角色提示词或Skill列表实现隔离。

## 明确未验证的事项

本轮仅提交文档和类型；没有handoff transport、消息发送、共享状态挂载、三bot编排或实际访问隔离部署。现有适配器仍只接受validate/compute，其他动作拒绝。没有修改用户已有机器人配置。此提案不声称已经证明live bot隔离。
